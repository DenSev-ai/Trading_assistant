# Инструкция для владельца проекта: что делать вам и на каком этапе

Кодит модель (Cline). Ваша работа: один раз подготовить окружение и ключи, на каждом шаге запустить модель, проверить результат и дать команду продолжать, а в конце накопить данные и принять решение. Всё, что нужно модели, уже лежит в репозитории.

## Если вы не понимаете, что делать дальше

Это нормально, никаких «глупых» вопросов тут нет. Идите по порядку:

1. **Посмотрите, где вы.** Откройте «Карту этапов» ниже. Идите строго сверху вниз: 0 → STEP_1 → STEP_2 → STEP_3 → STEP_4 → этап 5 → STEP_5 → STEP_6. Ваш текущий этап — первый, который вы ещё не закончили. Этапы не пропускайте и не меняйте местами.
2. **Прочитайте только свой этап.** Остальной текст пока не нужен.
3. **Выполняйте пункты по одному** и после каждого смотрите, получился ли результат, описанный в инструкции. Не получился — не идите дальше, переходите к п. 5.
4. **Не знаете, закончен ли этап?** Закончен, если выполнены все пункты, проверка из таблицы «Ручная проверка по шагам» даёт ожидаемый результат, а `pytest` и `ruff check .` проходят без ошибок.
5. **Что-то не получается или непонятно.** Откройте новую задачу в Cline и отправьте модели по шаблону:
```
Я новичок. Прочитай d:\My_projects\Trading assistant\docs\USER_GUIDE.md.
Я на этапе: <номер и название этапа>.
Я сделал: <что уже сделано, по пунктам>.
Не понимаю / не получается: <ваш вопрос своими словами>.
Вот что вижу на экране: <скопируйте текст ошибки целиком или опишите>.
Объясни простыми словами и скажи, какой ровно один следующий шаг мне сделать. Файлы не меняй, пока я не попрошу.
```
6. **Совсем потерялись?** Отправьте модели: «Посмотри файлы проекта в d:\My_projects\Trading assistant и скажи, на каком я этапе из USER_GUIDE.md и что мне делать прямо сейчас. Объясни простыми словами, без терминов». Модель проверит папку и подскажет.
7. **Главные правила, чтобы не навредить:**
   - ничего не удаляйте, если не уверены. Лучше спросите;
   - ключи и пароли никому не отправляйте и в чат не вставляйте. Вместо ключа пишите `<ключ>`;
   - ошибку копируйте целиком, а не пересказывайте. Так её быстрее исправить;
   - сломалось после вашей правки — скажите, что именно вы поменяли, и верните как было;
   - если вопрос не про код, а про сайты (OpenRouter, Telegram, GitHub), опишите, что видите на экране: название кнопки, текст сообщения.
8. **Куда смотреть в первую очередь при проблемах:** раздел «Частые проблемы» в конце этого файла и файл `data/errors.log` (появится после STEP_2).

## Карта этапов
| Этап | Ваши действия | Время | Результат |
|---|---|---|---|
| 0. Подготовка | ключи, git, окружение | 30–40 мин | проект готов к кодингу |
| 1–4. Код ядра (STEP_1, 2, 3A–3C, 4A–4E) | запуск модели на подшаг, проверка | 10–30 мин на подшаг | работают сбор, анализ, проверка, статистика, отчёты на почту |
| 5. Живой сбор данных | запуск `--once` по ситуации | 2–4 недели | накопленная статистика |
| 6. Telegram (STEP_5) | бот, ID чата | 15 мин + шаг | алерты и дайджест |
| 7. Автозапуск (STEP_6) | Планировщик Windows | 20 мин | сервис стартует сам |
| 8. Решение | `--report` и письма на почту | раз в неделю | вердикт по критерию: ≥ 75% сбывшихся при n ≥ 100 |

Нумерация: «этапы» — в этой инструкции, «шаги» — файлы `docs/steps/STEP_N.md`. Порядок кодирования: STEP_1 → 2 → 3 → 4 → 5 → 6.

## Этап 0. Подготовка (один раз)

**Быстрый путь (рекомендуется).** Скрипт `scripts\setup.ps1` сам делает пункты 0.3 (создаёт `.env`), 0.4 (git, первый коммит, отправка на GitHub) и 0.5 (`.venv` и библиотеки). Вам остаётся:
1. Получить ключ OpenRouter (пункт 0.1) и, когда дойдёте до этапа 6, Telegram-бота (пункт 0.2). Это делается на сайтах, скриптом не автоматизируется.
2. По желанию создать на GitHub пустой приватный репозиторий (пункт 0.4, шаг 1) и скопировать его адрес.
3. В PowerShell в папке проекта выполнить одну команду (без GitHub уберите часть после `setup.ps1`):
```
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -RemoteUrl https://github.com/<ваш_логин>/<репозиторий>.git
```
Скрипт может один раз спросить имя и e-mail для коммитов (любые). В конце он скажет `[OK]` или `[!] ОСТАЛОСЬ ВАМ: ...`, то есть что ещё сделать руками. Обычно это вписать `OPENROUTER_API_KEY` в `.env`.
4. Открыть `.env` в VS Code, вписать ключ (правила записи в 0.3, шаг 2), сохранить Ctrl+S.
5. Скрипт можно запускать повторно, ничего не сломается и не сотрётся.

Пункты 0.3–0.5 ниже описывают то же самое вручную. Они нужны, только если скрипт выдал ошибку.

**0.1. Ключ OpenRouter** (платные модели в боевой паре).
1. https://openrouter.ai → Sign in → Credits → пополните на $5–10 картой. Боевая пара (Claude Sonnet 5.5 + Grok 4.7) платная: при дневном лимите `llm.daily_budget_usd` = $0,50 ориентируйтесь на пополнение $10 на первые недели. Баланс от $10 открывает 1000 запросов/сутки у бесплатных моделей-кандидатов; на меньшей сумме лимит 50 в сутки, и они будут часто упираться в лимит (на работу боевой пары это не влияет).
2. Keys → Create Key. На ключе задайте Credit limit $5 — это внешний предохранитель от перерасхода.
3. Ключ сохраните в надёжном месте. В чат с моделью ключ НЕ вставляйте.

**0.2. Telegram-бот** (нужен к STEP_5, но можно создать сразу).
1. В Telegram откройте @BotFather → `/newbot` → имя и username → получите токен.
2. Откройте своего бота и нажмите Start.
3. Свой chat ID узнайте у бота @userinfobot (число `Id`). Для группы добавьте бота в группу и узнайте ID группы тем же способом (он отрицательный).
4. Telegram должен открываться на этом ПК напрямую (при необходимости включите VPN на уровне системы).

**0.3. Файл `.env` (ваши секретные ключи).**

*Что это такое.* `.env` — обычный текстовый файл, где лежат ваши пароли и ключи (ключ OpenRouter, токен бота). Программа читает его при запуске. Файл `.env.example` — это **образец**: в нём стоят только названия, без значений. Его не трогаем и никуда не вписываем ключи.

*Нужно ли создавать пустой `.env`?* Нет. Создавать пустой файл не надо. Нужно сделать **копию** образца под именем `.env` и вписать в неё свои значения. Делается один раз.

**Шаг 1. Сделайте копию.** Если вы запускали `scripts\setup.ps1` (см. «Быстрый путь» выше), файл уже создан, переходите к шагу 2. Вручную:
1. Откройте PowerShell в папке проекта. В VS Code: меню «Terminal» → «New Terminal». Строка внизу должна показывать `...\Trading assistant`.
2. Вставьте команду и нажмите Enter:
```
if (-not (Test-Path .env)) { Copy-Item .env.example .env; "Файл .env создан" } else { "Файл .env уже есть, ничего не менял" }
```
Команда сама проверяет, есть ли уже `.env`. Если он есть, она его **не тронет** (иначе уже введённые ключи были бы стёрты). Выполнять её нужно один раз.

*Без командной строки:* в проводнике нажмите на `.env.example` правой кнопкой → «Копировать», затем «Вставить», затем переименуйте копию в `.env` (точка в начале, **ничего после `env`**). Windows может предупредить об изменении расширения: ответьте «Да». Не открывайте и не сохраняйте файл через «Блокнот» командой «Сохранить как» с типом «Текстовые документы»: получится `.env.txt`, а программа ищет именно `.env`.

**Шаг 2. Откройте `.env` в VS Code** (двойной клик в списке файлов слева) и впишите значения сразу после знака `=`:
```
OPENROUTER_API_KEY=sk-or-v1-ваш-ключ
TELEGRAM_BOT_TOKEN=123456789:ABC-ваш-токен
TELEGRAM_CHAT_IDS=123456789
```
| Строка | Откуда взять значение | Обязательно? |
|---|---|---|
| `OPENROUTER_API_KEY` | пункт 0.1 (сайт OpenRouter → Keys) | **да**, без неё программа не работает |
| `TELEGRAM_BOT_TOKEN` | пункт 0.2 (бот @BotFather) | нет, до этапа 6 можно оставить пустым |
| `TELEGRAM_CHAT_IDS` | пункт 0.2 (бот @userinfobot, число `Id`) | нет, до этапа 6 можно оставить пустым |

Правила записи (на них чаще всего ошибаются):
- только значение, **без кавычек**: `KEY=abc`, а не `KEY="abc"`;
- **без пробелов** вокруг `=`: `KEY=abc`, а не `KEY = abc`;
- одна переменная на одну строку, лишние строки и комментарии не нужны;
- несколько получателей Telegram пишите через запятую без пробелов: `TELEGRAM_CHAT_IDS=111111111,222222222`;
- после правки сохраните файл (Ctrl+S).

**Шаг 3. Проверьте, что файл на месте.** В PowerShell в папке проекта:
```
dir .env
```
Должна появиться одна строка с именем `.env`. Это проверка, что файл создан в нужном месте (в корне проекта, рядом с `.env.example` и `requirements.txt`). Правильность содержимого проверяет команда `.venv\Scripts\python.exe -m trading_assistant --check-config`, но она заработает только после STEP_1. До этого момента её запускать бессмысленно: ошибка «No module named trading_assistant» ожидаема и означает лишь, что код ещё не написан.

**Важно:**
- `.env` перечислен в `.gitignore`, поэтому при `git add .` в GitHub он не попадёт. Всё равно никому не показывайте его содержимое и не вставляйте ключи в чат с моделью.
- Если модель при выполнении шага добавит в `.env.example` новые строки (например, ключи для новостных сервисов), откройте `.env.example`, перенесите эти новые строки в свой `.env` и впишите значения. Строки помеченные как необязательные можно оставить пустыми. Что именно нужно, скажет `--check-config`: `[НЕТ]` — надо заполнить, `[ОПЦИОНАЛЬНО]` — можно пропустить, `[OK]` — всё в порядке.
- Изменили `.env` — перезапустите программу: на лету файл не перечитывается.

**0.4. Git и приватный репозиторий** (`scripts\setup.ps1` делает пункт 2 сам; пункт 1 на сайте остаётся за вами).
1. Создайте на GitHub пустой приватный репозиторий (без README и без .gitignore).
2. В папке проекта выполните:
```
git init
git add .
git commit -m "Initial: spec v3, configs, step docs"
git branch -M main
git remote add origin https://github.com/<ваш_логин>/<репозиторий>.git
git push -u origin main
```
GitHub попросит войти через браузер. Токены в чат не отправляйте.

**0.5. Окружение Python** (`.venv` с библиотеками уже создано, `scripts\setup.ps1` проверит и доустановит; вручную, если нужно):
```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**0.6. Праздники.** В `config/settings.yaml` → `schedule.non_working_dates` внесите даты праздников РФ на ближайшие месяцы, формат `"2026-12-31"`. Сервис в эти даты и в выходные не работает. Пополняйте список раз в квартал.

**0.7. Модель-кодер.** Подойдёт любая в Cline, в том числе бесплатная. Каждый шаг начинайте в НОВОЙ задаче (новом чате) — так дешевле и надёжнее.

## Кодирование шагов (STEP_1 … STEP_6)

Порядок по времени: STEP_1 → 2 → **3A → 3B → 3C → 4A → 4B → 4C → 4D → 4E** → этап 5 (сбор данных, параллельно можно готовить Telegram) → STEP_5 (этап 6) → STEP_6 (этап 7). Шаги 3 и 4 разбиты на подшаги: каждый маленький, чтобы бесплатная модель не путалась. Для каждого шага N выполняйте одно и то же; вместо числа подставляйте имя подшага: `-Step 3A`, `-Step 4C` и т. д. Папка `tests\acceptance` — эталонные проверки основных правил (15%, 20%, 75%, выборка из 100): модель не должна их менять; пока код не написан, они «пропущены» (skipped), после подшагов 3B, 4A и 4C — должны проходить.

**Что вы делаете (3 действия на шаг):**
1. В PowerShell в папке проекта выполните (замените N на номер шага):
```
powershell -ExecutionPolicy Bypass -File scripts\start_step.ps1 -Step N
```
Скрипт сам составит стартовое сообщение для модели и **скопирует его в буфер обмена**. Откройте новую задачу в Cline и нажмите Ctrl+V, затем Enter.
2. Модель сама напишет код, сама запустит `pytest` и `ruff`, а затем сама выполнит `scripts\finish_step.ps1`. Этот скрипт ещё раз проверяет код и, **только если ошибок нет**, делает `git commit -m "Step N"` и `git push` (если GitHub подключён). Если Cline спросит разрешение на запуск команды, разрешите. Дождитесь фразы «Шаг N готов.»
3. Сделайте ручную проверку из таблицы ниже (1–2 минуты). Если результат не тот, вставьте в ту же задачу текст ошибки целиком. Модель исправит и снова выполнит `finish_step.ps1`, это создаст новый коммит.

Следующий шаг начинайте только после успешной ручной проверки.

Если модель не запустила `finish_step.ps1` (забыла, закончились лимиты), выполните его сами: `powershell -ExecutionPolicy Bypass -File scripts\finish_step.ps1 -Step N`. Если `pytest` или `ruff` нашли ошибки, скрипт остановится и коммит не создаст, это защита. Текст ошибки покажите модели. Только локальный коммит без отправки на GitHub: добавьте `-NoPush`.

**Ручная проверка по шагам:**
| Шаг | Что запустить | Что должно быть |
|---|---|---|
| 1 | `.venv\Scripts\python.exe -m trading_assistant --check-config` | `[OK] OPENROUTER_API_KEY`, для Telegram `[OK]` или `[ОПЦИОНАЛЬНО]`; значения ключей не печатаются |
| 2 | `.venv\Scripts\python.exe -m trading_assistant --once` | счётчики: получено, отфильтровано, без полного текста, кластеров; создан `data/app.log` |
| 3A | `pytest tests/test_run_model.py` | тесты проходят |

| 3C | `.venv\Scripts\python.exe -m trading_assistant --once --dry-run` | в итогах — число проанализированных кластеров и расход в долларах; нет ошибок 401/402 |
| 4A | `pytest tests/acceptance/test_acc_backtest.py` | проходит, не «skipped» |

**Живые тесты** (по желанию, в конце шагов 2, 3 и 4): `.venv\Scripts\python.exe -m pytest -m live`. Они делают реальные запросы к сайтам, OpenRouter (копейки) и MOEX. Если источник из таблицы SPEC §8 упал, отключите его в `config/settings.yaml` (`enabled: false`).

**Заглянуть в БД без программ:**
```
.venv\Scripts\python.exe -c "import sqlite3; c=sqlite3.connect('data/trading.db'); print(c.execute('select model,status,cost_usd from model_runs order by id desc limit 10').fetchall())"
```

**Если модель ошиблась.** Не пишите «исправь всё». Дайте одну конкретную ошибку (текст из консоли) или номер нарушенного пункта документа. После 2–3 неудачных попыток начните шаг заново в новой задаче — это дешевле длинного диалога. Если модель пишет, что документы противоречат друг другу или чего-то не хватает, правьте документ (или попросите об этом сильную модель), а не код.

## Этап 5. Живой сбор данных (после STEP_4, 2–4 недели)
Цель: накопить n ≥ 100 выданных и проверенных прогнозов консенсуса боевой пары (`evaluation.sample_n`). Прогнозы выдаются редко: нужны движение ≥ 15%, срок ≤ 180 дней, уверенность ≥ 85 и согласие двух моделей. Это нормально, у проекта принцип «лучше меньше, но точнее». Накопление может занять месяцы; значение `sample_n` и пороги в `signal.*` вы можете менять сами. До подключения отчётов на почту заполните `SMTP_*` и `REPORT_EMAIL_TO` в `.env` (пароль приложения Яндекс/Gmail, не основной пароль): тогда ежедневные, еженедельные и событийные письма придут автоматически; без них отчёты сохраняются в `data/reports/`. Пока Telegram не подключён, запускайте вручную:
1. В рабочие дни утром (после 08:00 МСК) выполните `.venv\Scripts\python.exe -m trading_assistant --once`. Для накопления данных лучше запускать несколько раз в день (утром, в обед, вечером) или оставить сервис работать (этап 7).
2. Раз в 2–3 дня запускайте `--report` и смотрите: сколько прогнозов (n), доля успешных, расход.
3. Прогноз считается сбывшимся, как только цена достигла движения ≥ 15% (по закрытию дня) в предсказанную сторону, и проверяется до `horizon_days` календарных дней (до 180). Первые цифры могут появиться уже через несколько дней, неудачные прогнозы закрываются только после срока.
4. Следите за расходом: стартовый лимит $0,50 в сутки (`llm.daily_budget_usd`). Если расход упирается в лимит — повышайте его сами по статистике из отчётов. Когда лимит исчерпан, сервис останавливает анализ до следующих суток (сначала кандидаты, пара — последней).
5. После первой недели откройте `data/app.log` и посмотрите, сколько новостей отсеивает предфильтр. Если сигналов слишком мало — расширьте `config/keywords.yaml`, если слишком много «шума» — сузьте. Пороги `signal.*` по ходу набора выборки не меняйте.

## Этап 6. Telegram (STEP_5)
1. Убедитесь, что `.env` содержит `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_IDS`.
2. Выполните шаг 5 по общей схеме (выше).
3. Проверка: `python -m trading_assistant --once` без `--dry-run` в рабочее время после 09:45 МСК. Сигнал придёт, если он есть. Команды боту `/start`, `/help`, `/status`, `/last`, `/stats SBER` должны отвечать. Чужой аккаунт не получает ответов.
4. Сигналы до 09:45 копятся и приходят утренним дайджестом.

## Этап 7. Автозапуск (STEP_6)
1. Выполните шаг 6 по общей схеме.
2. Включите таймеры пробуждения: Панель управления → Электропитание → Настройка схемы → Изменить дополнительные параметры → «Сон» → «Разрешить таймеры пробуждения» → «Включить» (для работы от сети).
3. Откройте PowerShell **от администратора** в папке проекта: `powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1`.
4. Проверка: Планировщик заданий → «TradingAssistant» → ПКМ → «Выполнить». В `data/app.log` должны появиться записи. Остановка: создайте файл `data\stop.flag` или дождитесь 22:40.
5. Желательно в BIOS ноутбука включить опцию пробуждения по RTC (Wake on RTC / Resume by Alarm), если она есть.
6. На ночь ноутбук должен засыпать сам (схема питания: сон при простое). Если утром пробуждение не сработало, запустите задачу вручную и сообщите об этом: тогда будем менять схему запуска.


## Этап 8. Решение по проекту
Раз в неделю читайте еженедельное письмо (или выполняйте `--report`) и смотрите последнюю строку:
- **«НАКОПЛЕНИЕ ДАННЫХ (n=N из 100)»** — продолжайте работу, решений не принимайте.
- **«ПРОЕКТ ПРИГОДЕН»** (≥ 75% сбывшихся при n ≥ 100) — идея работает. Сервис сам начинает тесты более дешёвых моделей-кандидатов (`llm.candidates`), они работают молча и пользователю ничего не отправляют.
- **«ПРОЕКТ НЕ ПРИГОДЕН»** (< 75% при n ≥ 100) — идея в текущем виде не работает. Не дорабатывайте Telegram и интерфейс: пересматривайте промт (и меняйте `llm.prompt_version`), пороги `signal.*` или набор источников и накопите новую выборку. Не подгоняйте пороги под уже полученные данные.

**Выбор модели (CONTRACTS §9):** каждая модель оценивается отдельно по своим выданным прогнозам. Модель с долей сбывшихся < 75% отбрасывается, даже если она дешёвая. Среди моделей с долей ≥ 75% лучшей считается та, у которой меньше «стоимость вызовов, давших выданные прогнозы ÷ процент сбывшихся». Тест каждой модели заканчивается после `evaluation.sample_n` (100) прогнозов. Сервис присылает предложение замены на почту и в Telegram, но пару меняете ТОЛЬКО вы: правка `llm.pair` в `config/settings.yaml` и перезапуск. Пара должна состоять из моделей разных разработчиков близкого уровня. После смены пары или `prompt_version` статистика по новой паре начинается с нуля, в алерте до `n = 30` пишется «статистики пока мало».

## Частые проблемы
| Симптом | Что делать |
|---|---|
| `[НЕТ] OPENROUTER_API_KEY` | заполните `.env`; файл должен лежать в корне проекта |
| Ошибка 401 от OpenRouter | неверный ключ — создайте новый |
| Ошибка 402 | закончились деньги на балансе или достигнут лимит ключа |
| Ошибка 429 у бесплатных моделей | исчерпан суточный лимит бесплатных — норма для моделей-кандидатов |
| Нет сообщений в Telegram | проверьте токен, chat ID, что нажали Start у бота, доступность Telegram и что сейчас ACTIVE-фаза (после 09:45 МСК) |
| Сервис не стартует утром | Планировщик → история задачи; ПК не проснулся — см. этап 7, п. 5–6 |
| `finish_step.ps1`: «pytest нашёл ошибки» / «ruff нашёл замечания» | коммит не создан намеренно; покажите текст ошибки модели в той же задаче, она исправит и повторит скрипт |
| `finish_step.ps1`: «push не удался» | коммит уже создан локально; проверьте интернет и вход в GitHub, затем в папке проекта `git push` |
| «Выполнение сценариев отключено» при запуске `.ps1` | запускайте именно так: `powershell -ExecutionPolicy Bypass -File scripts\имя.ps1` |
| «Уже запущен» | остался процесс: диспетчер задач → завершите `pythonw.exe`; при необходимости удалите `data\service.lock` |
| Источник новостей перестал отвечать | в `config/settings.yaml` поставьте у него `enabled: false` |
